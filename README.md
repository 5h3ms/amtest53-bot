# amtest53-bot

Telegram-бот для подготовки к тесту на гражданство Армении. Русские объяснения, армянские вопросы, карточки, повторения и пробный тест.

## Что работает

- Личные чаты и закрытый список участников.
- Занятия примерно на 15 минут, сохранение текущего шага и прогресса.
- Карточки с переводом по запросу и повторениями через 1, 3, 7, 14 и 30 дней.
- Тренировочные вопросы с переводом и объяснением; ошибки чаще появляются в практике.
- Пробный тест: 33 разных вопроса, 60 минут, порог 17. Подсказки выключены, ошибки разбираются в конце.
- Напоминания по времени и часовому поясу пользователя, по умолчанию выключены.
- Локальный запуск без облачного проекта и оплаты; подготовлены функции для Firebase.

Контент первой версии: **40 авторских тренировочных вопросов, 824 слова и выражения, 88 уроков**. Из присланных Excel-словарей добавлены 764 новые карточки и дополнены две существующие. Есть отдельные разделы существительных, глаголов и других слов. Это не подтверждённый текущий официальный банк экзамена. Ссылки на статьи и дата проверки сохранены в вопросах. Подробнее: [источники и ограничения](content/SOURCES.md).

## Быстрый запуск на Windows

Нужны Node.js 22.12 или новее в ветке 22, npm и интернет. Telegram можно открыть на телефоне или компьютере. Для самого простого запуска Java и Firebase не нужны.

```powershell
git clone https://github.com/5h3ms/amtest53-bot.git
cd amtest53-bot
npm ci
Copy-Item .env.example .env.local
notepad .env.local
```

В `.env.local` вставьте токен из BotFather в `BOT_TOKEN`. Этот файл исключён из Git. Токен не нужно присылать в чат или добавлять в исходный код.

Затем узнайте свой Telegram ID:

```powershell
npm run identify
```

Отправьте `/start` своему боту. Команда покажет в терминале ваш числовой ID. Нажмите `Ctrl+C`, впишите этот ID в `ALLOWED_USER_IDS` и `ADMIN_USER_IDS` в `.env.local` и запустите:

```powershell
npm run dev
```

На Windows также можно использовать `./start-local.ps1 identify` и `./start-local.ps1 dev`. Скрипт запускается из каталога проекта и при необходимости находит стандартную установку Volta.

Откройте бот в Telegram и отправьте `/start` ещё раз. Пока программа работает, бот отвечает. `Ctrl+C` останавливает его; сохранённый прогресс остаётся в `.local/state.json`. Переустановка или обновление исходного кода этот файл не затрагивает. Локальный прогресс не переносится в облако автоматически.

Для нескольких участников укажите их ID через запятую. Администратор также должен присутствовать в `ALLOWED_USER_IDS`. Пользователи вне списка не получают доступ. На этапе настройки используйте только свой чат; `identify` выводит ID всех приславших `/start` приватных пользователей.

Если установлен Volta и команда `node` сообщает, что не может определить каталог установки, задайте `VOLTA_HOME` в этом же PowerShell по фактическому пути установки (обычно `$env:VOLTA_HOME = Join-Path $env:LOCALAPPDATA 'Volta'`), затем повторите команду. В проекте нет зависимости от WSL или Docker.

## Проверки

```powershell
npm run check
npm run build
```

Тесты проверяют работу учебной логики, повторные события, таймер, подсказки, пользователей и хранилища. Они не отправляют реальные сообщения в Telegram. Реальную работу токена и доставки проверяет владелец отдельным запуском.

### Firestore Emulator

Для проверки серверного хранилища понадобится Java 21. CLI Firebase установлен в зависимостях проекта.

```powershell
npm run emulator
```

Во втором терминале измените только локальный файл `.env.local`:

```dotenv
LOCAL_STORAGE=firestore
FIRESTORE_EMULATOR_HOST=127.0.0.1:8080
GCLOUD_PROJECT=demo-amtest53-bot
```

Затем `npm run dev`. Эмулятор экспортирует данные при нормальной остановке и импортирует их при следующем запуске. Адрес интерфейса: `http://127.0.0.1:4000`. Локальный режим откажется запускаться с облачным Firestore вместо эмулятора.

Отдельная интеграционная проверка с временным эмулятором:

```powershell
npm run test:emulator
```

## Публикация

Целевой проект: `amtest53-bot`. Производственный режим использует Firebase Functions второго поколения и Firestore. Blaze нужен только для публикации. Пошаговая инструкция: [Firebase deployment](docs/DEPLOYMENT.md).

GitHub Actions выполняет проверки при push и pull request; автоматическая публикация в Firebase не включена. Для итераций создавайте ветку, делайте небольшие коммиты и открывайте pull request в `main`.

## Данные и секреты

Публичны код, тесты, конфигурация без секретов, примеры настроек и авторский пилотный контент. Telegram-токен, секрет webhook и список реальных участников хранятся локально или в Secret Manager. Прогресс хранится в локальном файле/Firestore, а не в Git. Используется штатная identity Firebase: скачивать JSON-ключ service account не нужно.

`/privacy` объясняет хранение данных. `/reset` предлагает подтвердить сброс учебного прогресса и напоминаний; Telegram ID остаётся техническим ключом записи. Для полного удаления записи и резервных копий обратитесь к владельцу бота. Результаты ограничены последними 30 тестами, идентификаторы обработанных событий — последними 200 событиями.

Перед публикацией запускайте `npm run secrets:check` и проверяйте `git diff --cached`. Простая проверка шаблонов не гарантирует обнаружение всех секретов. При утечке токен надо отозвать/заменить, а не только удалить строку из нового коммита.

## Обновление курса

Редактируйте `content/course.json`, сохраняйте стабильные ID и повышайте версию. `npm run content:check` проверяет структуру и ссылки. Начатые занятия сохраняют снимок вопросов, поэтому обновление не меняет задания посередине. Новые материалы сначала проверяются по источникам и на допустимость публикации; личные таблицы храните только в исключённом каталоге `private-materials/`.

Для словарей из таблиц предусмотрен [проверяемый импорт](docs/IMPORT.md) с объединением повторов и созданием коротких уроков.

## Ограничения первой версии

- Пилотные армянские формулировки ещё не проходили независимое ревью носителем языка.
- Один локальный процесс на файл состояния. Облачная версия рассчитана на небольшую закрытую группу.
- При редком сбое между отправкой Telegram и сохранением подтверждения сообщение может повториться; баллы повторно не начисляются.
- Напоминания не отправляются задним числом после длительного простоя. Таймер экзамена привязан к сохранённому сроку, даже если уведомление о завершении задержалось.
- Официальный банк экзамена, разбор неоднозначных строк и грамматических схем из таблиц, а также реальная облачная публикация — следующие этапы.
- При проверке 28.10.2026 у производственных зависимостей нет известных уязвимостей в `npm audit`. У Firebase CLI остаются две проблемы умеренной серьёзности в транзитивных зависимостях разработки (пять узлов дерева); исправлений в текущей версии CLI пока нет. CLI не входит в производственные зависимости бота.
