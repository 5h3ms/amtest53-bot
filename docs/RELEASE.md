## Открытый доступ

По запросу владельца используется `ACCESS_MODE=public`: любой пользователь может открыть личный чат с ботом и отправить `/start`. Добавление его ID в первоначальный список не требуется. Администраторами остаются только явно указанные `ADMIN_USER_IDS`; чужой прогресс недоступен через пользовательские команды.

Параметр `ACCESS_MODE` хранится в Secret Manager и подключён к обеим функциям. Для возврата к закрытому режиму задайте `private`, проверьте список `ALLOWED_USER_IDS` и опубликуйте обе функции. Это меняет доступ, но не удаляет сохранённый прогресс.

Напоминания и таймеры обслуживают зарегистрированных пользователей страницами по 100, без прежнего ограничения списка на 1000 записей. Неактивные записи читаются без лишней записи в базу. При значительном росте аудитории следует перейти к запросам по времени следующего события; текущий просмотр остаётся линейным по числу зарегистрированных участников.

Проверены регистрация без списка ID, ответы, раздельный прогресс, граница прав администратора, отзыв доступа в закрытом режиме и работа напоминаний. Реальный Firestore Emulator прошёл обход 1005 документов без пропусков и дублирования.

## Оптимизация расхода Firestore — 29 октября 2026 года

Штатная успешная доставка команды или нажатия использует два чтения и две записи вместо трёх. Резервирование отправки выполняется вместе с сохранением события; подтверждение проверяет токен владельца. Неизменившиеся состояния повторно не записываются. Сетевые ошибки и дополнительные сообщения очереди требуют дополнительных операций.

После проверенного переноса метаданных расписание выбирает только наступившие события по `nextMaintenanceAt`. Полное чтение неактивной аудитории каждые пять минут устранено. Сводка владельца и частоты ответов кэшируются на 10 минут; участники читаются по пять записей с переходами вперёд и назад. Тексты сообщений об ошибках остаются в исходных пользовательских документах.

Проверки: 360 тестов без эмулятора, 10 проверок реального Firestore Emulator, TypeScript, сборка и поиск секретов. Включены бюджет из двух транзакций на доставку, конкурентные повторы, устаревшие отправители и обновления кэша, выборка среди 1000 неактивных записей, часовые пояса и DST, переключение старой схемы, сохранение исходного JSON при backfill и повторный запуск миграции.
