# Расход операций Firebase

## Обычное действие

Успешная команда или нажатие кнопки с одной доставкой теперь выполняет две транзакции пользователя: сохранение события вместе с резервированием отправки и подтверждение доставки после Telegram. Каждая транзакция читает и записывает один документ: штатный путь — два чтения и две записи вместо трёх. Повторные попытки транзакций, ошибки сети, очередь ранее недоставленных сообщений и административные отчёты требуют дополнительных операций.

Временное право отправки содержит случайный токен владельца. Просроченный отправитель не может подтвердить или освободить право нового отправителя. Только первый элемент очереди резервируется заранее; остальные захватываются перед своей отправкой. После временной ошибки повтор разрешён через минуту. Если отправка прошла, но подтверждение потерялось, повторная отправка всё ещё возможна: Telegram и Firestore не поддерживают общую транзакцию. Существующая защита от повторного учёта ответов сохраняется.

Firestore не выполняет запись, если сохранённый JSON и служебные метаданные не изменились. Проверка уже завершённого повторного update поэтому требует чтения, но не лишней записи. Большой JSON не разбивается на отдельную запись для каждой метрики.

## Фоновая работа

`nextMaintenanceAt` хранится вне JSON и обновляется атомарно с ним. Это минимум из срока экзамена, времени готовности/повтора/истечения сообщения и следующего напоминания. У пользователя без ожидающих событий значение `null`. Учитываются местное время, переходы часовых поясов и прежнее десятиминутное окно напоминаний.

Расписание сохраняет частоту раз в пять минут, но после проверенного переноса метаданных запрашивает только наступившие записи по индексу. Неактивная аудитория больше не перечитывается 288 раз в сутки. Пагинация использует время и ID документа, без платных offset-пропусков. Страница до 100 элементов дополнительно читает один элемент для определения продолжения.

Когда наступивших событий нет, остаются чтение маркера готовности и минимальная стоимость пустого запроса; работа не становится совершенно бесплатной. При наступивших событиях добавляются чтения выбранных документов и транзакции обработки/доставки. Время функций, резервные копии, развёртывания и другие сервисы оплачиваются отдельно по применимым тарифам. Лимиты экземпляров не являются денежным лимитом.

Для существующих документов требуется один проход метаданных, описанный в [DEPLOYMENT.md](DEPLOYMENT.md). До его успешного завершения продолжает работать прежний обход. Сам перенос не меняет учебный прогресс, сессии, настройки, аналитику или сообщения пользователей.

## Отчёты владельца

Сводка и частоты ответов кэшируются на 10 минут в Firestore и доступны другим экземплярам функции. Обновление выполняется только по обращению владельца и по-прежнему требует одного полного чтения аудитории. Кэш разбит на ограниченные блоки; опубликованный снимок заменяется атомарно, прежние блоки удаляются. Одновременные и запоздавшие обновления защищены проверкой владельца в транзакциях. При сбое сохраняется предыдущая сводка, повторный пересчёт откладывается на минуту.

Последующие страницы вопросов и сообщений читают только манифест и нужный блок. Тексты сообщений не копируются в кэш: хранится ссылка, по которой читается один пользователь. Список участников запрашивает пять документов и один элемент продолжения, а не всю аудиторию. Кнопка «Назад» использует индекс поля `key`: Firestore не поддерживает обратный скан системного ключа документа.

Статистические счётчики не записываются в общий документ при каждом ответе. Поэтому пользовательская активность не создаёт конкуренцию за одну глобальную запись. Дата сводки видна владельцу; новые события могут появиться в ней с задержкой до следующего обновления.

Тесты проверяют количество транзакций штатной доставки, выборку среди 1000 неактивных записей, реальный индексированный запрос Firestore, сохранение байтов JSON при переносе, гонки отправителей и обновлений кэша.
